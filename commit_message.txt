refactor: Inline depthOf logic and remove dead code from EarthDepth

This commit addresses a code health issue identified in the `EarthDepth` component located at `src/world/earth/EarthDepth.jsx`. The goal is to improve the maintainability and readability of the codebase by eliminating unnecessary abstractions and dead code.

Initially, there was a `depthOf` function exported from `EarthDepth.jsx`. Upon closer inspection, it was determined that this function was not intended to be a public API and was only used internally within the same file to calculate the opacity of earth tiles. To simplify the component and reduce the API surface area, the `depthOf` function was first converted to a local function by removing the `export` keyword.

However, to fully resolve the issue and eliminate the abstraction entirely, the logic within the `depthOf` function was extracted and inlined directly into the `opacity` prop of the `path` element within the `EarthDepth` component's render method. This completely removes the need for the `depthOf` function, making it dead code, which was then deleted from the file. This inline approach makes the component slightly more straightforward, as the calculation is explicitly visible where it's used without having to jump to a separate function definition.

Furthermore, since the `depthOf` function was originally exported, it was documented in the corresponding mirror markdown file `docs/daten/earth/earthdepth.md` under the `## Schnittstellen` section. To keep the documentation in sync with the module exports, the reference to `depthOf()` was removed from the markdown file. This ensures the documentation accurately reflects the current state of the codebase.

These changes were verified by running the full test suite (`pnpm run verify`) and the CI gate checks (`pnpm run gate`), which confirmed that the modifications did not introduce any regressions and successfully passed all project policies, including code limits and import rules.
